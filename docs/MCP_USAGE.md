# MessagingMatrix MCP — Tool Reference

This document describes every tool the MessagingMatrix MCP server exposes, what inputs each accepts, what it returns, and how to compose them. Use it as a reference when driving the matrix from Claude.ai, Claude Desktop, Cowork, or any MCP-speaking client.

**Server versions:** v5.1.0 (see `CHANGELOG.md`).
**Endpoint:** `https://<instance>.messagingmatrix.ai/mcp/?secret=<TOKEN>` — per-instance, where `<instance>` is one of `erste`, `telekom`, `proficio`, `demo`. Each instance has its own Google Sheet as the source of truth, its own DB, and its own bearer token.

For setup see `docs/MCP_SERVER.md`. This document is about **using** the tools, not installing them.

---

## Mental model — what the matrix actually is

A messaging matrix is a grid of **audiences × topics**, where each cell holds zero or more **messages** (called MCs, short for Messaging Cards). Each MC is the content + creative spec for a specific ad variant targeted at a specific audience around a specific topic.

- **Audience** — who you're targeting. Has a `key` (short handle like `VAL_adaptive`), a `name` (human-readable), a `product`, `strategy`, `buying_platform`, `device`, etc. Also holds campaign / line-item identifiers.
- **Topic** — what you're saying. Has a `key` (like `VAL_benefit_elorejutas_toke`), a `name`, a `product`, and up to 4 tags. The key is deterministically generated from a pattern (usually involving product + tags).
- **MC** (message) — the actual creative content. Identified by its **MC label** `MC<number><variant>` (e.g. `MC282a`, `MC290b`). Holds: audience_key, topic_key, template name, status, headline, copy1/2, CTA, disclaimer, image1..image6, video1, landing URL, and derived fields (PMMID, trafficking UTM strings).
- **MC label** — a human-friendly ID. Always starts with `MC`, then an integer (1+), then a single lowercase variant letter (`a`, `b`, `c`, …). Examples: `MC1a`, `MC282a`, `MC1360z`.
- **Status** (workflow status) — where the MC sits in the creative pipeline. Common values: `INCOMING`, `NAMING`, `CONTENT`, `PREVIEW`, `APPROVED`, `ACTIVE`, `INACTIVE`, `ERROR`, `DEAD`, `MEMORY`. These come from the configured keyword list, not a fixed enum.
- **Monitoring status** — whether the creative is *actually running* on AdForm right now. Values: `live` / `inactive`. Derived from the `Reporting` tab populated by the Monitoring → AdForm Sync, NOT from the workflow status above. A creative can be `ACTIVE` (approved internally) but `inactive` on AdForm (campaign paused), or vice versa.
- **Template** — the HTML design the creative renders in (e.g. `html`, `NobilisTilia-html`). Dictates which sizes are supported and which placeholder slots exist.
- **PMMID** — a derived tracking identifier like `a_VAL_adaptive-t_VAL_benefit_...-m_282-v_a-n_1`. Auto-generated by the server when `mc_create` or `mc_update` touches audience/topic/number/variant/version.

The MCP tools are thin surface over the Google Sheet: reads pull from the sheet, writes use single-row Google Sheets API PUT/append/delete. Nothing goes through the React UI.

## Auth + transport (one-paragraph summary)

Every tool call is a JSON-RPC request over Streamable HTTP. Claude.ai connectors authenticate via `?secret=<token>` in the URL query string; Claude Desktop / curl can use `Authorization: Bearer <token>` header instead. Either alone is sufficient. Wrong or missing token → 401.

## Tool reference

All inputs use lowercase snake_case. Property names for the `updates` object in update-tools match the **sheet header row** of the corresponding tab (typically Capitalized, e.g. `Name`, `Product`, `Headline`, `Landing_URL`). Use a `list_*` tool once to see the actual header names for your instance.

### Write — audiences

#### `audience_create`
Append a new row to the Audiences sheet.

| Input | Type | Notes |
|---|---|---|
| `name` | string (required) | Display name |
| `product` | string | |
| `strategy` | string | |
| `buying_platform` | string | |
| `device` | string | |
| `data_source` | string | |
| `targeting_type` | string | |
| `tag` | string | |
| `key` | string | Override auto-generated key |
| `order` | number | Override auto-incremented order |
| `status` | string | |
| `comment` | string | |
| `campaign_name` | string | |
| `campaign_id` | string | |
| `lineitem_name` | string | |
| `lineitem_id` | string | |

**Auto-behavior:** `ID` is auto-incremented (max existing + 1). `Order` defaults to max existing + 1. `Key` defaults to `aud<order>`.

**Returns:**
```json
{
  "created": { "id": 166, "key": "aud166", "name": "VAL_retargeted_savers" },
  "wroteRow": ["166", "VAL_retargeted_savers", "166", "", "szk", ...]
}
```

**Example:**
```
audience_create({
  name: "VAL_retargeted_savers",
  product: "szk",
  strategy: "pro",
  buying_platform: "adform",
  device: "wid"
})
```

#### `audience_remove`
Delete one row from the Audiences sheet. Provide either `key` or `name`.

| Input | Type | Notes |
|---|---|---|
| `key` | string | Match by audience key (preferred) |
| `name` | string | Match by exact name |

**Gotcha:** if MCs reference this audience's `key`, they keep the key but become orphaned from an audience object. The UI shows them with empty audience. Fix up MCs with `mc_update` afterwards if needed.

#### `audience_update`
Modify an existing audience row, matched by `key`.

| Input | Type | Notes |
|---|---|---|
| `key` | string (required) | Current audience key |
| `updates` | object (required) | Header-name → new value |

**Example:**
```
audience_update({
  key: "VAL_adaptive",
  updates: { "Strategy": "con", "Device": "mob" }
})
```

### Write — topics

#### `topic_create`
Append a new topic. Key is generated via the configured `topicKey` pattern (typically `<product>_<tag1>_<tag2>...`); if the pattern isn't set it falls back to `top<order>`.

| Input | Type | Notes |
|---|---|---|
| `name` | string (required) | |
| `product` | string | |
| `tag1` — `tag4` | string | Tags are often used in the key pattern |
| `order` | number | Override auto-increment |
| `status` | string | |
| `comment` | string | |
| `key` | string | Override auto-generated key |

#### `topic_remove`
Delete by `key` or `name`. Same orphaning caveat as `audience_remove`.

#### `topic_update`
Update topic row. **Auto-behavior:** if `product`, `tag1`, `tag2`, `tag3`, or `tag4` changes, the key is regenerated from the pattern. Use `mc_update` on any message referencing the old key if you don't want them to break.

### Write — MCs (messages)

#### `mc_create`
Append a new MC row. This is the flagship write tool.

| Input | Type | Notes |
|---|---|---|
| `audience_key` | string (required) | Must exist in Audiences |
| `topic_key` | string (required) | Must exist in Topics |
| `template` | string (required) | Name from `list_templates`, e.g. `html` |
| `status` | string | Default `INCOMING` |
| `headline` | string | |
| `copy1` | string | |
| `copy2` | string | |
| `cta` | string | CTA button text |
| `disclaimer` | string | |
| `flash` | string | Sticker / flash text |
| `image1` — `image6` | string | Drive file ID or filename |
| `video1` | string | |
| `landing_url` | string | |
| `comment` | string | |
| `number` | number | Override auto-numbering |
| `variant` | string | Single lowercase letter override |
| `version` | number | Default 1 |

**Auto-behavior:**
- `number`/`variant` default to "next free in this audience×topic cell": if the cell already has MCs the new row gets the same `number` and the next variant letter (`a` → `b` → `c`…). If the cell is empty, it gets `<max_number_globally + 1>` and variant `a`.
- `PMMID` and trafficking fields (`utm_campaign`, `utm_content`, `final_trafficked_url`, etc.) are regenerated from the configured patterns.
- `ID` is auto-incremented.

**Returns:**
```json
{
  "created": {
    "id": 1361,
    "mc_label": "MC1361a",
    "pmmid": "a_VAL_adaptive-t_VAL_benefit_elorejutas_toke-m_1361-v_a-n_1"
  },
  "wroteRow": [...]
}
```

**Example:**
```
mc_create({
  audience_key: "VAL_adaptive",
  topic_key: "VAL_benefit_elorejutas_toke_penzemdolgozik",
  template: "html",
  headline: "Kezdj befektetni már 1 000 Ft-tól",
  copy1: "Indíts Erste Azonnali Megtakarítást.",
  cta: "Legyek Erste",
  image1: "1HzEfaL-bg-savings-v1.jpg",
  landing_url: "https://erste.hu/megtakaritas"
})
```

#### `mc_remove`
Delete an MC row by label.

| Input | Type | Notes |
|---|---|---|
| `mc_label` | string, matches `MC\d+[a-z]` | e.g. `MC282a` |

#### `mc_update`
Modify an MC row by label.

| Input | Type | Notes |
|---|---|---|
| `mc_label` | string (required) | |
| `updates` | object (required) | Header-name → new value |

**Auto-behavior:** if `audience_key`, `topic_key`, `number`, `variant`, or `version` change, PMMID + trafficking fields are regenerated. Other changes (headline, copy1, CTA, etc.) leave PMMID untouched.

**Example — change status + headline:**
```
mc_update({
  mc_label: "MC282a",
  updates: { "Status": "ACTIVE", "Headline": "Kezdj befektetni már 500 Ft-tól" }
})
```

**Example — move MC to a different audience (triggers PMMID regen):**
```
mc_update({
  mc_label: "MC282a",
  updates: { "Audience_Key": "VAL_adaptive-targeted" }
})
```

### Read — audiences / topics / MCs

#### `list_audiences`
Returns all Audience rows as objects, optionally filtered by product.

| Input | Type |
|---|---|
| `product` | string (optional) — case-insensitive match against the `Product` header |

**Returns:**
```json
{
  "count": 165,
  "audiences": [
    { "ID": "1", "Name": "VAL_adaptive", "Key": "VAL_adaptive", "Product": "", "Strategy": "pro", ... },
    ...
  ]
}
```

#### `list_topics`
Same shape as `list_audiences`, for Topics.

#### `list_mc`
List MCs with multi-axis filtering.

| Input | Type | Notes |
|---|---|---|
| `topic_key` | string | Filter by Topic_Key |
| `audience_key` | string | Filter by Audience_Key |
| `product` | string | Joins against the audience's Product — returns MCs whose audience belongs to this product |
| `status` | string | Workflow status, case-insensitive exact match — e.g. `ACTIVE`, `INCOMING` |
| `monitoring_status` | `"live"` / `"inactive"` | Joins against the Reporting sheet's label-level AdForm_Status. `live` = AdForm reports impressions. `inactive` = not live (including MCs with no Reporting row at all). |

All filters combine with AND. Empty input returns every MC in the sheet.

**Returns (compact projection — use `mc_get` for full fields):**
```json
{
  "count": 668,
  "messages": [
    {
      "mc_label": "MC282a",
      "audience_key": "VAL_adaptive-targeted",
      "topic_key": "VAL_benefit_elorejutas_toke_penzemdolgozik",
      "status": "ACTIVE",
      "template": "html",
      "headline": "Kezdj befektetni már 1 000 Ft-tól",
      "copy1": "Indíts Erste Azonnali Megtakarítást.",
      "cta": "Legyek Erste",
      "pmmid": "a_VAL_adaptive-targeted-t_VAL_benefit_..."
    },
    ...
  ]
}
```

**Example — all ACTIVE MCs live on AdForm for the "szk" product:**
```
list_mc({ product: "szk", status: "ACTIVE", monitoring_status: "live" })
```

#### `mc_get`
Full row of one MC.

| Input | Type |
|---|---|
| `mc_label` | string (required) |

Returns every field the Messages sheet carries (headline, copy1/2, cta, disclaimer, flash, image1..6, video1, landing_url, comment, status, PMMID, trafficking UTMs, etc.). Use this before `mc_update` to see the current shape.

### Reporting

#### `get_mc_reporting`
Return AdForm performance data for an MC. Reads the `Reporting` sheet written by the Monitoring → AdForm Sync.

| Input | Type |
|---|---|
| `mc_label` | string (required) |

**Returns:**
```json
{
  "mc_label": "MC282a",
  "label": {
    "impressions": 220918,
    "clicks": 399,
    "ctr": 0.0018,
    "live": true
  },
  "banners": [
    { "size": "300x250", "banner_id": "14234745", "banner_name": "Erste_..._300x250_...",
      "status": "live", "impressions": 72102, "clicks": 132, "ctr": 0.0018 },
    { "size": "300x600", "banner_id": "14234746", "banner_name": "Erste_..._300x600_...",
      "status": "live", "impressions": 68904, "clicks": 125, "ctr": 0.0018 },
    ...
  ]
}
```

- `label` is the rollup across all banner sizes for this MC label.
- `banners` is per individual banner (per size).
- `ctr` is a 0–1 fraction (multiply by 100 to display as %).
- `label.live` = any banner was live.
- If the MC has no matching rows in the Reporting sheet, returns `label: null, banners: [], note: "Reporting sheet is empty — run the AdForm sync first"`.

### Meta

#### `list_templates`
Returns every template available for `mc_create`.

Returns an array of `{ name, sizes: [{width, height, name}], placeholders: [...] }`. Sizes are derived from `<w>x<h>.css` filenames in each template directory; placeholders from each template's `template.json`. Use this before creating an MC to pick a valid template + know which image slots / sizes will actually render.

Example response entry:
```json
{
  "name": "html",
  "sizes": [
    { "width": 300, "height": 250, "name": "300x250" },
    { "width": 300, "height": 600, "name": "300x600" },
    { "width": 640, "height": 360, "name": "640x360" },
    { "width": 970, "height": 250, "name": "970x250" }
  ],
  "placeholders": ["background_image_1", "background_image_2", "headline_text_1", "copy_text_1", "cta_text_1", ...]
}
```

#### `list_products`
Sorted unique `Product` values across Audiences + Topics.

Returns e.g. `{"products": ["babyloan", "beerste", "diakszamla", "jelzalog", "szk", ...]}`.

Use as the source of truth for the `product` filter in `list_audiences` / `list_topics` / `list_mc`.

#### `matrix_status`
High-level counts for the instance.

```json
{
  "audiences": 165,
  "topics": 80,
  "messages": {
    "total": 1360,
    "by_status": {
      "ACTIVE": 925,
      "INACTIVE": 386,
      "INPROGRESS": 1,
      "PLANNED": 14,
      "CONTENT": 3,
      "INCOMING": 31
    }
  },
  "last_reporting_sync": "2026-04-22T20:50:09.513Z"
}
```

Good sanity check when first connecting ("am I pointed at the right instance?") and for reporting staleness (`last_reporting_sync` tells you how old the Monitoring data is).

## Workflow recipes

### "Show me the top 10 creatives by CTR currently running"
```
1. list_mc({ status: "ACTIVE", monitoring_status: "live" })
   → grab mc_label for each
2. For each mc_label: get_mc_reporting(mc_label)
   → sort by label.ctr descending, take 10
```

Claude composes this naturally without needing a dedicated tool.

### "Create a copy variant B for MC282"
```
1. mc_get("MC282a")
   → read audience_key, topic_key, template, current headline / copy1 / cta
2. mc_create({
     audience_key, topic_key, template,
     headline: <new variant>,
     copy1: <new variant>,
     cta: <new variant>
   })
   → auto-picks MC282b (same cell, next variant)
```

### "Move all MC variants of MC290 to a different audience"
```
1. list_mc() → filter by number 290 locally (or use mc_label regex)
   OR: list by (topic_key of MC290a's topic, audience_key of MC290a's audience)
2. For each mc_label found:
   mc_update({ mc_label, updates: { "Audience_Key": "<new_audience_key>" } })
```

### "Mark all MCs with INCOMING status as DEAD"
```
1. list_mc({ status: "INCOMING" })
2. For each mc_label: mc_update({ mc_label, updates: { "Status": "DEAD" } })
```

### "Audit all audiences without a product assigned"
```
1. list_audiences()
2. Filter locally for Product === ""
3. audience_update each to set a Product
```

### "Which MCs performed under 0.1% CTR in the last reporting window?"
```
1. list_mc({ monitoring_status: "live" })
2. For each: get_mc_reporting
3. Filter label.ctr < 0.001 locally
```

## Limitations — read before relying on this

### 1. Concurrency with the matrix UI
The matrix UI saves with a full-table rewrite (`saveAll` writes every row of Audiences / Topics / Messages / Creatives / TextFormatting in one shot). If you use MCP to add/modify a row **while the UI is open with unsaved edits**, then click Save in the UI, the UI's rewrite will overwrite your MCP change. Rule of thumb:

- **Save any pending UI edits before running MCP tools.**
- **Reload the UI after MCP batches to see the changes.**

MCP tools themselves are single-row operations and don't collide with each other.

### 2. Google Sheets API quotas
Every read/write hits the Sheets API. The service account is shared with the UI. Bulk operations (e.g., `mc_update` on 500 rows in a loop) can hit the per-minute write quota. Back off or batch manually. Current observed ceiling: ~60 writes/minute per service account before 429s appear.

### 3. Header-name case-sensitivity in `updates`
The `updates` object's keys must match the spreadsheet's actual header row (e.g. `"Status"` not `"status"`, `"Audience_Key"` not `"audience_key"`). Case-insensitive matching is a best-effort fallback, but when in doubt use the exact casing from `list_*` output.

### 4. No preview image
`mc_preview_image` is deliberately deferred. To see a rendered preview, open the matrix UI → Creative Library → the MC. There is no MCP way to fetch a PNG of the rendered creative yet.

### 5. Instance isolation
Each subdomain's MCP endpoint only sees that instance's Google Sheet. There's no cross-instance query — you can't ask `mm-erste` about Telekom data. If you want to compare across instances, run the same tool on each and diff client-side.

### 6. Monitoring status lags behind reality
`monitoring_status` and `get_mc_reporting` read the `Reporting` sheet, which is only refreshed when someone hits "Sync now" on the Monitoring page (or a scheduled sync fires — not implemented yet). `matrix_status.last_reporting_sync` tells you how stale. Live campaigns won't appear as `live` until the next sync.

### 7. `list_mc` returns a compact projection
To keep responses small, `list_mc` returns only the display-relevant fields. To read the full row (flash, disclaimer, all 6 images, trafficking URLs, etc.), follow up with `mc_get(mc_label)`.

### 8. `mc_create` doesn't validate referential integrity
It won't block you from creating an MC pointing at an `audience_key` or `topic_key` that doesn't exist. The UI would show it as an orphan. Always check with `list_audiences` / `list_topics` first if you're composing at scale.

### 9. `topic_update` and topic-key regeneration
Changing `product` or a tag auto-regenerates the topic's key. MCs that reference the old key will become orphaned. There's no cascade — follow up with `mc_update` on each affected MC.

### 10. No authentication per user
The bearer token is instance-wide. Anyone with the token can do anything. Rotate it (via `openssl rand -hex 32` + `.env` update + PM2 restart + client config update) if it leaks.

### 11. Delete is permanent
`audience_remove` / `topic_remove` / `mc_remove` are full DELETE on the row. There's no "status: deleted" soft-delete. To preserve history, use `*_update` to set a status like `DEAD` instead.

### 12. Rate of change → UI hot-reload not automatic
The React matrix UI caches data in memory. After MCP changes, the UI will only show them on next full reload (F5) — there's no push notification from server to UI.

### 13. AdForm sync runs manually
The `get_mc_reporting` numbers are only as fresh as the last manual Monitoring → Sync. The AdForm live-API path in `services/adformService.js` is currently backed by a local xlsx (see `data/adform-report.xlsx`). Switching to the live API is a separate operator step.

## Error shapes

All errors come back as JSON-RPC errors with `code` and `message`:

- `401 Unauthorized` (HTTP-level, not JSON-RPC) — wrong or missing `?secret=` / `Authorization` header.
- `503 Service Unavailable` — `MCP_BEARER_TOKEN` env var not set on the server.
- `{ code: -32603, message: "..." }` — internal tool error (Sheets API failure, missing row, parsing issue). The message is verbatim from the underlying layer; inspect it.
- `{ code: -32602, message: "..." }` — bad input (schema validation failure). Fix the call and retry.
- `"MC <label> not found"` — `mc_get` / `mc_update` / `mc_remove` on a label that doesn't exist.
- `"Audience key \"X\" not found"` / `"Topic key \"X\" not found"` — same for audience/topic updates.
